# The Router delivers by ZMQ identity, not by its registration table

Every element sets its ZMQ identity to its own name. The Router therefore sends straight to `destination.encode()` with `ROUTER_MANDATORY` on, and lets libzmq's live connection table decide whether the peer is reachable (`EHOSTUNREACH` becomes a `DESTINATION_UNREACHABLE` error). The Router's own record of registrations (the Directory) is kept only for diagnostics: element kind, last seen, and known names in error messages.

We chose this because the old registration dicts were stale in both directions. After a Router restart they refused connected Clients, which never re-register. After a Provider crash they "found" dead Providers, and libzmq silently dropped the message. To keep the identity == name assumption true, the Router rejects any Packet whose `source` does not match the identity frame it arrived on. Transport-level ZMQ heartbeats (`ZMQ_HEARTBEAT_IVL`/`_TIMEOUT`) close half-open connections quickly. Provider REGISTRATION beats are still sent so that Providers re-register after a Router restart, and they update last seen. Missed beats never mark a Provider offline, because a Provider sends no beats while running a long Operation.
